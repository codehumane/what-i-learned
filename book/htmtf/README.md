## 6장. 지연

- 대기열 지연과 일관성 지연 이야기
- 케빈의 송장 생성 프로그램 성능 저하 이야기로 시작
- 블록 읽기 수가 불필요하게 많아서 이를 제거했다는 내용
- 암달의 법칙 얘기도 나옴 = 1 / ((1-p) + p/s)
- 이 읽기 수 감소는 대기열 지연<sup>queueing delay</sup>도 함께 줄임
- 아래 표와 수식의 대기열 이론도 소개
- M/M/2 모델로 설명함
- 책이 말하고자 하는 바는, 언제 대기 지연이 늘고, 전체 응답에 어떤 영향을 미치는지
- 그리고 이 그래프 모양은 쌍곡선

| 기호 | 의미 |
| -- | -- |
| $\lambda$ | 초당 평균 요청 도착 수 |
| $\mu$ | 자원 하나가 계속 일할 때 초당 평균 처리 가능한 요청 수 |
| $\rho = \lambda / (2\mu)$ | 각 자원의 평균 이용률 (책에선 트래픽 강도라고 표현) |
| $S = 1 / \mu$ | 평균 처리 시간 |
| $Q$ | 평균 대기 시간 |
| $R$ | 대기를 포함한 평균 응답 시간 |

$$
R = Q + S = \frac{S}{1 - \rho^2}
$$
$$
Q = R - S = \frac{\rho^2}{1 - \rho^2}S
$$

- 일관성 지연도 가볍게 소개
- 대기 지연은 한계 효용을 감소시키는데,
- 일관성 지연은 부하가 늘어날 때 오히려 최대 처리량보다 처리량이 낮아질 수도
- "주문을 입력하는 직원을 한 명 더 채용했는데, 시스템의 분당 주문 처리량은 오히려 낮아짐"의 상황과 같음
- 뒤에서 다루겠지만 램프 문제<sup>ramp problem</sup> 때문

## 7장. 낭비

- 이어서 다루겠다고 한 램프 문제가 바로 나옴
- 다만, 일반적으로 램프가 널리 쓰이는 용어인지는 의문
- [저자의 블로그 글](https://carymillsap.blogspot.com/2010/04/ramp.html)도 함께 참고
- 시간이 지나면서 점점 선형적으로 악화되는 성능 문제를 가리킴
- 그리고 이 누적은 1 + 2 + 3 + ... + N = N(N + 1)/2
- 즉 N^2에 비례하는 문제이므로 더 심각
- `지정한 파라미터에 대한 속도의 변화율`이라는 확장성 정의도 소개
- 개발 관점에서는 지금까지 특별한 내용은 없었음
- 다만, 조직 구조 관점에서도 최적화/지연/낭비가 중요한 문제라서, 다시 곱씹어 보게 됨
- 한 사람을 더 투입했는데 오히려 느려진다? 일관성 지연이자 램프 문제일 수도
- 채용을 계속 하는데 인원수 대비 조직 생산성이 올라가지 않았다? 조직이 작을 땐 문제 없던 것들이 드러나기 시작
- 채용을 늘리지 않고 수수께끼 얘기처럼 카운트를 줄이거나 평균값을 줄일 수도 있음
- 확장성의 정의도 조직에서 중요한 문제 (스케일링 가능해야 하고 기울기가 높을수록 좋음)
